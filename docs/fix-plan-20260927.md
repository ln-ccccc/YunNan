## 批次 A：数据正确性（P1）

### A-1 时间序列化统一补 Z（修 #1）
- 主模块：`backend/applications/schemas/project.py`；消费方：miner 前端 formatDateTime（已正确处理 Z）。
- 改法：新增 `UtcDateTime` 字段类（serialize 时 naive 即视为 UTC 补 `Z`），替换 `ProjectExportRecordSchema.create_time/update_time`、`ProjectBackupRecordSchema.create_time/update_time`、`ProjectLatestInferenceSchema.create_time` 三处 naive dump。同文件顺手审计其余 DateTime 字段，仅动有 GUI 消费的。
- 依据：DB/后端容器均 UTC（实测 `NOW()==UTC_TIMESTAMP()`）；timeline 走 `_utc_timestamp` 已带 Z 且前端显示正确。
- 验证：新增 pytest 断言 backups/exports/latest_inference 三接口时间以 Z 结尾且与 timeline 同记录一致；GUI 复测快照/导出时间显示 22:53 风格。

### A-2 面积单位链路修复（修 #2）
- 主模块：`backend/applications/project_hub/project_map.py`（stats 聚合）。
- 根因：project 1 绑定导入将 area 映射到 `SHAPE_Area`（平方度）；聚合优先 `binding.area_snapshot` → 万公顷量级假值 0.0007；前端按 m²÷10000 显示公顷 → 0.00。
- 改法：聚合取值优先级改为 `properties.area → properties.TBTYMJ → binding.area_snapshot`（官方图斑面积 TBTYMJ 为 m²）；不动存量绑定数据（读路径修复即可回滚）。areaStats 阈值（1e6 m²）随之恢复语义。
- 验证：pytest 断言 mineAreaTotal≈全 features TBTYMJ 之和（m² 量级）且 small/medium/large 计数正确；GUI 复测「监测面积」显示非零公顷。

### A-3 解译进度日期格式（修 #6）
