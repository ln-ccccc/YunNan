# M5 计划：智能解译收编主控台（Segementation 工作流迁移）

> 状态：计划已制定，M5.1 实施中。承接 2026-09-22 主控台化计划（M1-M4 已交付）与用户 2026-09-25 决策：**不重构解译平台前后端**，按"功能归属收编"推进——把推理发起与历史浏览迁入 Miner 主控台，解译平台收敛为纯工具页（矢量编辑器 + 光谱指数）。

## 1. 背景与目标

用户观察"解译平台耦合度高、不好修改"。实测数据：前端 33 文件/4598 行（最大 770 行）、后端 14760 行 11 包、三端测试基线 981/47/76 全绿——经 2026-09-22 重构后已非屎山。真正的结构性问题是**最后一个大块功能分裂**：推理发起与历史浏览仍住在解译平台 Segmentation 页，主控台"智能解译"导航为占位。

目标：把"上传 → 预处理 → 推理 → 历史浏览 → 转编辑"工作流收编进 Miner，使解译平台失去"必须先去解译平台"的存在感。完成后用户日常工作流全部在 :4000 一个端口完成。

## 2. 现状盘点（2026-09-25 实测）

### 解译平台 Segmentation 承载的工作流
1. **上传**：tif/tiff（文件夹拖拽/单文件/ENVI 成对），年份 YYYY（KML ROI 命名），预处理选项 CLAHE/锐化/平滑/滤波。上传栈已组件化（TiffUploadCard + getUploadImg/upload → Flask `imgUpload/createSrc`）。
2. **推理**：开始处理 → Flask mmseg 按 KML ROI 推理 → 产物（原图/预测结果）按组展示（ImgShow 卡片）。
3. **历史**：两组 API——普通历史 `/api/history/list|removeOne`（按 type）；KML ROI 项目态历史 `/api/analysis/kml_roi_history`(GET/DELETE，带 project_id)。每组卡片有"编辑矢量成果"跳转。
4. **转编辑**：组卡片 → ClassificationResultEditor（`/classification-results/editor?project_id&result_id`）→ 保存新修订版本。

### Miner 已有（可复用）
- InferenceModal（地图页"添加矿山与解译"）：单矿山推理发起 + 进度轮询 + 取消（inferenceBackend + inferencePolling）。
- 影像管理页：分片上传/格式适配/裁剪/切片（S1-S4 基建）。
- 图斑编辑页：分类成果清单 + 编辑矢量跳转（今日已修跨端 P1）。
- 溯源/图斑清单/统计：成果消费端已全部就绪。

### 缺口
主控台没有"推理历史浏览"与"批区推理发起"页面；智能解译导航占位。

## 3. 分期

### M5.1 智能解译页 v1（只读收编）— 本期实施
- Miner 新页面 `SmartInterpretationView.vue`（占位导航 `#/interpretation` 转正）：
  - 项目选择器 + KML ROI 推理历史列表（矿山/年份/状态/产物缩略/时间）；
  - 每条成果"编辑矢量"入口（复用图斑编辑页的 origin 拼接逻辑）；
  - "发起新解译"引导至地图工作台现有推理入口（v1 不重复造发起 UI）。
- BFF 新增 `routes/interpretation.js`：`/api/analysis/kml_roi_history` GET/DELETE 转发（鉴权与既有 relay 同构，上游计数断言守卫）。
- 后端零改动（接口已存在）；导航施标"已上线"。
- 验证：BFF 转发测试（成功/无数据/参数错误/上游失败四态）+ 视图 helper 纯函数测试 + miner 全量 + build + GUI 截图走查。

### M5.2 上传与预处理收编
- 智能解译页内嵌上传：复用 Miner 影像管理已有上传组件（TiffUploadCard/分片分流），目标目录对齐 Flask `imgUpload` 语义（BFF 转发上传接口）。
- 年份 + CLAHE/锐化/平滑/滤波选项表单化。
- 验证：同 S 系列惯例（真文件端到端 + 临时目录）。

### M5.3 推理发起收编
- 页面内发起批区推理：项目态（选矿山/年份/影像）与 standalone 双模式，进度轮询/取消复用 InferenceModal + inferencePolling 基建。
- 推理完成 → 历史列表自动刷新 → 一键转编辑。

### M5.4 收敛收尾
- 会话过期联动提示（Miner 会话失效时统一引导，避免双端分别失效）。
- 解译平台导航收敛：保留矢量编辑器与光谱指数直达；操作提示文案更新。
- 智能解译导航项最终施标与文档同步。

## 4. 边界决策（默认执行，可推翻）

| 决策 | 取值 | 理由 |
| --- | --- | --- |
| 历史数据源 | KML ROI 项目态历史（`/api/analysis/kml_roi_history`）为主，普通历史仅在 standalone 场景展示 | 主控台一切按项目上下文组织，与 M1-M4 口径一致 |
| 推理发起 UI | v1 复用地图页 InferenceModal 入口，M5.3 再页面内化 | 发起流程已被 Modal 覆盖，先交付浏览价值 |
| 上传组件 | 复用 Miner 影像管理已有上传栈（含分片） | 同源同栈，避免第二套上传实现 |
| 后端 | 零改动（M5.1/M5.2 只加 BFF 转发） | 接口已存在，981 测试护着 |

## 5. 明确不做

- 解译平台前后端推倒重构（2026-09-25 已决策不做的理由见会话记录）。
- 光谱指数计算迁入主控台（保留在解译平台）。
- WebSocket 实时进度（沿用既有轮询）。
- 删除解译平台或其登录（编辑器仍需独立入口）。

## 6. 验收口径

每期交付：该期验证 + miner/frontend/backend 三套既有基线不回退 + GUI 截图走查（双通道）+ 真实栈操作（上传/推理/编辑至少各一次真数据演练）。文档随期同步（development-standard §7 命令、本计划回填勾选）。
