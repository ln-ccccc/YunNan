# 深度审计问题修复计划

基线：`main d0b37b5`。目标：修复 2026-10-11 已复现的影像处理、下载、异步交互与编辑状态问题，并重跑真实矿山和连续 GUI 验收。原工作区 `backend/test_project_management.py` 的用户修改纳入验证，保持文件不变。

## 边界与实现选择

沿用 Miner → BFF → Flask、GeoView → Flask 的现有依赖方向、接口、目录、模型与视觉系统，不升级依赖、不部署、不直接合并 main。四组使用独立工作树，汇总到 `codex/audit-remediation-20261011`。

影像提供方负责安全路径与空间规则。登记的 `incoming/` 相对路径按 PROJECT_STORAGE_ROOT 解析；新裁剪/切片继续写 `projects/<id>/inputs/imagery/`，数据库保存相对键，推理允许当前项目该目录的受支持栅格。历史物理路径不得公开；受控历史兼容只限存储根目录及当前项目，不能放宽任意路径输入。路径字段保持原名称；兼容详情的不可公开路径返回空值，新增安全 `storage_key` 如有需要须同步契约和 fixture。

候选影像响应增加可空 `bounds`，含义为 EPSG:4326 `[west,south,east,north]`，不含物理路径。Miner 框选消费真实范围；缺少地理参考时明确禁用框选。缓冲使用局部米制投影，输出仍是包围窗口而非多边形掩膜；窗口向外取整，保留源 NoData / 有效掩膜，不降低分辨率。快照可恢复 incoming 和本项目影像相对引用，跨项目与目录遍历继续拒绝。

BFF 成功下载保持流式传输；连接/响应头超时在收到头后清除，下游取消联动上游；流错误只终止本次响应。失败体有界读取，透传状态、类型和附件名。

前端仅对当前项目、查询或成果的当前请求应用回包。编辑器保存不能覆盖后来编辑；脏状态重载/离开须确认，409 保留修改。地图卸载先释放延迟交互；项目瓦片覆盖区外 404 不应误移除正常影像。沿用 Liquid Glass 材质、motion 和减少动态效果支持。

## 最小命令与风险

Miner / BFF：`cd miner; npm test`、`npm run build`、真实网络下载回归。GeoView：`cd frontend; npm test`、`npm run build`。后端：在既有运行镜像与临时 SQLite/目录下运行对应 unittest 模块，最终跑现有完整回归。

重点风险：历史路径兼容与项目归属、文件系统/数据库补偿、米制投影和旋转栅格、旧请求的 finally、浏览器延迟缩放、保存中继续编辑。出现新证据先补复现，再选最小修复；不屏蔽页面错误、不修改旧审计证据、不改变模型预处理。
