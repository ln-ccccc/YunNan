# 单管理员全站登录设计

## 1. 目标

- 为当前 YunNan 系统增加单管理员登录能力，管理员账号固定为 `admin`。
- `miner` 前端全站必须登录后才能访问，包括项目工作台、矿山地图和相关只读/写操作。
- 相关后端业务接口在未登录状态下必须统一拒绝访问，不能仅依赖前端隐藏页面。
- 忘记密码时，允许通过修改 Docker 环境变量并重启服务来重置管理员密码。

## 2. 约束

- 使用场景限定为本机或内网，不按公网系统设计。
- 一期只做单管理员，不做注册、多用户、角色权限和找回密码。
- 不在前端保存明文密码、JWT 或长期令牌。
- 必须基于当前 `backend + miner` 双后端结构落地，不重构成新架构。

## 3. 选定方案

采用“`backend` 统一认证 + 服务端会话 + `miner` 前端登录门禁”的方案。

- 管理员账号和密码校验放在 `backend`。
- 登录成功后由 `backend` 写入服务端会话，并通过 HttpOnly Cookie 维持登录态。
- `miner` 前端启动时先检查当前会话，未登录则只显示登录页，不渲染业务界面。
- `miner/server.js` 继续作为前端 API 入口，但受保护接口必须校验登录态，不能绕过 `backend` 直接读业务数据。

不采用以下方案：

- 仅在 `miner` 做登录：后端接口边界不完整，容易形成绕过点。
- JWT 前后端分离：对单管理员内网系统是过度设计，且前端持有令牌的风险更高。

## 4. 系统边界

### 4.1 受保护范围

以下内容默认全部要求登录后才能访问：

- `miner` 页面路由：`#/projects`、`#/map` 及其衍生页面
- `miner` API：`/api/projects`、`/api/stats`、`/api/geojson`、`/api/mines/*` 及后续登录页调用的业务接口
- `backend` 项目化接口及与当前前端联动的业务接口

### 4.2 登录后页面行为

- 默认访问 `http://localhost:4000/` 时先请求会话接口。
- 未登录：只显示登录页，不显示项目工作台、地图、统计卡片和业务数据。
- 已登录：进入默认业务页，优先回到 `#/projects`。
- 登录过期或退出后：立即清空前端业务状态并跳回登录页。
- 顶栏显示当前用户 `admin` 和“退出登录”按钮。

## 5. 认证与会话设计

### 5.1 账号模型

管理员固定为单账号：

- `username = admin`

不开放前端修改用户名。

### 5.2 密码存储

- 数据库中只存 `password_hash`。
- 使用强密码哈希算法，不存明文密码。
- 登录失败时返回统一错误提示，不区分“用户名错误”还是“密码错误”。

### 5.3 会话策略

- 使用服务端会话。
- 浏览器仅持有 HttpOnly Cookie。
- Cookie 至少包含：
  - `HttpOnly`
  - `SameSite=Lax`
- 会话失效后，所有受保护接口统一返回 `401`。

### 5.4 登录失败保护

- 对登录接口增加基础限流。
- 在短时间内连续失败多次时，短暂拒绝后续尝试。
- 限流范围按当前部署场景设计为单机/内网可接受的最小实现，不引入复杂外部依赖。

## 6. 初始化与重置密码

通过 Docker 环境变量初始化管理员：

- `ADMIN_USERNAME=admin`
- `ADMIN_PASSWORD=<你的密码>`

启动逻辑：

- 如果数据库中不存在 `admin`，自动创建。
- 如果存在 `admin`，则根据环境变量更新密码哈希。

这样可以满足以下运维方式：

- 忘记密码时，修改 `ADMIN_PASSWORD`
- 重启容器
- 使用新密码登录

## 7. 数据模型

在 `backend` 新增最小管理员表，字段只保留本次需求所需内容：

- `id`
- `username`
- `password_hash`
- `is_active`
- `last_login_at`
- `created_at`
- `updated_at`

不预留无关扩展字段，不做权限表，不做角色表。

## 8. 接口设计

### 8.1 认证接口

- `POST /api/auth/login`
  - 入参：`username`、`password`
  - 成功：写入会话，返回当前用户信息
  - 失败：返回统一失败信息

- `POST /api/auth/logout`
  - 销毁当前会话

- `GET /api/auth/session`
  - 返回当前是否已登录，以及当前用户是否为 `admin`

### 8.2 业务接口行为

- 所有受保护接口在未登录时统一返回 `401`
- 前端收到 `401` 后统一执行：
  - 清空页面状态
  - 跳转登录页
  - 提示“登录已过期，请重新登录”

## 9. 前端设计

### 9.1 登录页

登录页提供：

- 用户名输入框
- 密码输入框
- 登录按钮
- 统一失败提示区域

用户名默认允许手动输入，但实际只接受 `admin`。

### 9.2 路由守卫

前端在进入业务页前必须先完成会话检查：

- 未登录访问 `#/projects`
- 未登录访问 `#/map`
- 直接输入地址栏访问业务页面

上述情况都必须被拦回登录页。

### 9.3 顶栏状态

现有顶栏中的“管理员”展示改为真实登录状态展示：

- 已登录显示 `admin`
- 提供退出登录按钮

## 10. 安全要求

本次实现至少满足以下安全底线：

- 密码只存哈希，不存明文
- 不把密码、JWT、长期 token 写入 `localStorage` 或 `sessionStorage`
- 受保护接口不能只靠前端判断
- 登录失败提示不能泄露账号是否存在
- 登录接口带基础限流
- 退出登录后服务端会话必须失效

本次不纳入范围：

- 多因素认证
- 短信/邮箱验证码
- 公网 HTTPS 网关部署
- 找回密码流程
- 多角色权限体系

## 11. 测试与验收

### 11.1 后端测试

至少覆盖：

- 正确密码可登录
- 错误密码登录失败
- 未登录访问受保护接口返回 `401`
- 退出登录后再次访问返回 `401`
- 环境变量可创建 `admin`
- 修改环境变量后可重置 `admin` 密码

### 11.2 Node / 前端测试

至少覆盖：

- 未登录默认显示登录页
- 登录成功进入业务页
- 未登录直接访问 `#/map` 会被拦截
- 未登录直接访问 `#/projects` 会被拦截
- 会话失效后自动回到登录页

### 11.3 集成验收

至少覆盖：

- `4000` 前端必须先登录后使用
- `miner` API 未登录不能直接读业务数据
- `backend` 受保护接口未登录不能访问

### 11.4 完成后的附加要求

本需求完成后，必须额外执行两件事：

- 做一次全面测试
  - 包括后端测试、前端测试、容器内联调和关键 UI 路径验证
- 做一次针对本次改动范围的代码 review
  - 重点检查鉴权绕过、Cookie 会话边界、明文泄露、401 处理遗漏、回归风险和测试缺口

## 12. 实施边界

本次只实现“安全可用的单管理员登录系统”，不顺手扩展：

- 用户管理页面
- 权限管理页面
- 公网部署能力
- 额外账号体系
- 无关 UI 重构

如果后续需要多用户、细粒度权限、审计增强或公网安全加固，应作为下一阶段独立需求处理。
