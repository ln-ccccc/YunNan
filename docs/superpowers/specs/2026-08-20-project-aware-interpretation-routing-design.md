# 项目感知解译结果路由设计

日期：2026-08-20  
状态：用户已批准总体方向，待书面设计复核  
关联设计：`2026-07-19-project-spatial-instance-design.md`、`2026-07-16-inference-runtime-pipeline-design.md`

## 1. 目标

修复 `/segmentation` 当前因 CORS 预检被鉴权拦截而无法创建推理任务的问题，并让地物分类、变化矩阵和光谱指数按照明确的项目上下文路由结果：

- 从某个项目地图进入解译平台时，只使用该项目当前激活的矿山矢量进行空间匹配；
- TIFF 与当前项目矿山匹配时，将结果同步到对应矿山弹窗；
- TIFF 未匹配矿山，或用户直接打开解译平台且没有项目上下文时，只在解译平台展示结果；
- 项目之间禁止交叉匹配、交叉读取或交叉写入。

优先级为：项目数据隔离与结果正确性 > 可验证性 > 现有页面兼容 > 修改规模。

## 2. 已确认的业务规则

1. 当前项目由 Miner 地图页面显式传递，后端不得扫描所有项目猜测归属。
2. 大理项目只读取大理项目当前激活的矿山 KML/GeoJSON；切换到昆明后只读取昆明项目资源。
3. 直接访问 `/segmentation` 且没有 `project_id` 时进入独立解译模式，不关联任何项目。
4. 项目模式下，TIFF 与当前项目矿山多边形存在真实有效像元重叠时，视为匹配该矿山；仅包围盒相交但没有有效像元重叠不算匹配。
5. 一张 TIFF 可以匹配当前项目内多个矿山，结果按 FID 分别发布。
6. 地物分类结果在解译平台始终可见；只有项目匹配成功时才同步矿山弹窗。
7. 某矿山新增一个年份的地物分类后，变化矩阵使用同项目、同 FID 中时间上最近的更早年份作为基线。
8. 没有更早年份时只保存本年地物分类，不生成变化矩阵。
9. 光谱指数复用同一项目和空间匹配规则；匹配时按 FID 同步，未匹配时只保留解译平台结果。

## 3. 非目标

- 不增加项目选择器；项目上下文来自当前 Miner 地图。
- 不扫描全部活动项目寻找可能匹配的矿山。
- 不使用“最近打开的项目”会话状态推断项目。
- 不改变推理模型、推理精度、CPU 回退策略或 Worker 并发模型。
- 不迁移或删除已有全局历史结果。
- 不放宽规范项目 API 的项目 ID、矿山绑定和目录边界。
- 不顺带重构项目工作台、地图渲染或无关接口。

## 4. 项目上下文传递

Miner 当前已经以 `#/map/{project_id}` 表示所选项目。地图页跳转解译平台时，应把该 ID 写入 GeoView URL 的查询参数：

```text
http://127.0.0.1:3000/segmentation?project_id=123
```

GeoView 在当前页面生命周期内保留该值，并在地物分类、任务查询和光谱指数请求中显式提交。刷新或复制该 URL 后仍指向同一项目，避免会话状态和多标签页串项目。

没有查询参数时，前端不补默认项目 ID，后端进入独立解译模式。

## 5. 空间归属解析器

后端使用一个共享的空间归属解析单元，为地物分类和光谱指数提供同一结果。输入为可选 `project_id` 和已上传 TIFF 的受控路径，输出至少包含：

```text
mode: project | standalone
project_id: integer | null
mine_resource_id: integer | null
matched_fids: integer[]
warnings: string[]
```

解析步骤：

1. 验证 TIFF 路径位于允许的临时上传目录中，拒绝路径穿越和任意宿主路径。
2. 没有 `project_id` 时直接返回独立解译模式，不加载任何项目矿山资源。
3. 有 `project_id` 时验证项目存在且未删除，并读取该项目最新的 `active` 矿山空间资源。
4. 读取 TIFF CRS、仿射变换、尺寸、有效数据掩膜和地理范围。
5. 将项目矿山几何转换到 TIFF CRS；先用包围盒缩小候选集，再用多边形掩膜确认真实有效像元重叠。
6. 只保留同时存在于当前项目矿山绑定表中的 FID，并按稳定顺序返回。

指定项目不存在或没有激活矿山资源属于项目配置错误，应返回明确错误，不能静默回退到大理全局 KML。TIFF 缺失或无法解析 CRS 时仍可做独立像素解译，但必须返回“无法进行项目空间关联”的警告，且不得同步项目数据。

## 6. 地物分类数据流

### 6.1 上传与任务创建

文件继续先写入现有临时上传目录。创建任务前调用空间归属解析器：

- 独立模式或 `matched_fids` 为空：创建无项目归属的推理任务，输出只供 GeoView 历史与当前页面展示；
- 项目模式且存在匹配：将 TIFF 原子复制到 `project_storage/projects/{project_id}/inputs/interpretation/{year}/`，任务绑定 `project_id`、激活矿山资源版本和 `matched_fids`，输出根目录固定在该项目目录内。

项目任务使用复制后的项目路径，临时上传路径不直接进入规范项目 Worker 输入白名单。任务创建成功后不得因用户切换页面而改变项目归属。

### 6.2 推理与发布

Worker 继续复用现有异步任务、模型常驻、CPU 回退、超时、取消和部分失败机制。每个匹配 FID 是独立发布单元：

- 分类图、掩膜、类别面积占比和年份元数据写入 `projects/{project_id}/outputs/inference/{fid}/{year}/`；
- 成功发布后登记或更新 `ProjectDataset(dataset_kind="inference_result")`，记录项目、FID、年份、文件路径、任务 ID、源矿山资源版本和模型运行信息；
- 相同项目、FID、年份再次成功推理时原子替换该年份的当前结果，不新增歧义重复项；失败时保留上一份成功结果；
- 一个 FID 失败不得发布该 FID 的不完整结果，其他成功 FID 可以按现有 `partial_failed` 语义发布。

解译平台使用任务返回的结果 URL 展示，不再拼接固定全局 `miner/change_matrix_outputs` 路径。

## 7. 变化矩阵与地物分类弹窗

每个项目、FID 的成功分类结果按年份索引。新结果发布后：

1. 查找严格小于当前年份的最大年份；
2. 找到时，以该年份为 `old_year`、当前年份为 `new_year` 生成变化矩阵和两期分类图引用；
3. 找不到时只更新分类结果，项目变化矩阵接口返回“已有分类、暂无历史基线”；
4. 所有历史年份和年份对保留在项目存储中，矿山弹窗默认展示 `new_year` 最大的有效年份对；
5. 补传较早年份时，重新计算受影响的相邻年份对，但不能用较老年份覆盖弹窗中更新的年份对。

矿山弹窗继续通过项目接口读取：

```text
GET /api/projects/{project_id}/mines/change-matrix?fid={fid}
```

项目摘要写入 `projects/{project_id}/outputs/change_matrix/{fid}.json`，其中包含实际 `old_year`、`new_year`、矩阵、类别统计和项目内资源 URL。前端不得继续硬编码年份标签。

## 8. 光谱指数数据流

NDVI、NDBI、NDWI、NDSI 使用与地物分类相同的 `project_id` 传递和空间归属解析器：

- 独立模式或无矿山匹配：计算整幅有效影像指数，在 GeoView 中保存和展示，不写项目输出；
- 项目匹配：按每个匹配 FID 的真实多边形掩膜计算统计值，写入 `projects/{project_id}/outputs/indices/{fid}.json`；
- 指数记录以项目、FID、指数类型和年份区分，相同年份重复计算时更新该点；
- 项目矿山弹窗继续通过 `/api/projects/{project_id}/mines/indices?fid={fid}` 读取，不能回退到全局 Excel 或其他项目输出。

现有光谱指数预览图和 GeoView 分析历史保持兼容；项目同步失败应作为结构化警告返回，不能把已成功的独立计算伪装成全部失败。

## 9. CORS、鉴权与路径安全

- 受保护蓝图允许合法来源的 `OPTIONS` 预检通过；预检不创建会话、不访问业务数据。
- 实际 `POST`、`GET` 和取消请求继续要求有效登录会话。
- 前端 3000、Miner 4000 与后端 5008 继续使用现有允许来源和凭据策略。
- 项目 ID 必须由后端校验；矿山 FID 必须属于该项目当前绑定集合。
- 临时输入只允许位于上传根目录；项目输入和输出只允许位于 `projects/{project_id}` 根目录。
- 项目任务不得读取全局 `miner/yunnan.kml`、其他项目资源或调用方提交的任意 KML 路径。

## 10. 错误处理与用户反馈

- CORS 预检失败不再被错误显示为“后端未启动”。
- 未登录的真实请求返回“登录已失效”。
- 项目不存在、项目无激活矿山资源、TIFF 路径越界、年份非法分别返回可定位的 4xx 错误。
- TIFF 无 CRS、CRS 无法转换或没有矿山重叠时，推理可继续以独立模式完成，但响应必须明确说明未同步项目数据的原因。
- 任务成功提示包含“仅解译平台展示”或“已同步到 N 个矿山”，避免用户猜测数据去向。
- Worker 失败继续返回具体任务错误；前端不得用通用网络异常覆盖后端业务消息。

## 11. 兼容性与数据保留

- 保留 `/segmentation` 路径、上传方式、年份输入和异步轮询交互。
- 保留已有独立解译历史和旧全局输出的只读能力，本次不迁移、不删除。
- 新产生的项目关联结果只写项目存储；不再双写全局大理目录。
- 规范 `/api/inference/jobs` 的项目隔离不放宽；旧 `/api/analysis/kml_roi_inference` 作为 GeoView 兼容入口，负责解析可选项目上下文后调用共享任务创建逻辑。
- 不改变推理任务既有状态字段；新增项目归属、匹配 FID 和同步摘要均为兼容性字段。

## 12. 测试策略

### 12.1 后端单元与 API 测试

- 合法来源的受保护 `OPTIONS` 返回成功并包含 CORS 头；未登录真实请求仍返回 401。
- 无 `project_id` 创建独立任务，不读取项目矿山资源。
- 大理项目请求只读取大理活动矿山资源，昆明资源即使空间相交也不参与。
- TIFF 无重叠、单矿山重叠、多矿山重叠、仅包围盒相交、缺失 CRS分别得到明确结果。
- 输入路径越界、FID 不属于项目、项目无活动资源均被拒绝或按设计降级。
- 同 FID 首年只发布分类；第二年选择最近更早年份生成矩阵；补传历史年份不覆盖最新年份对。
- 相同年份重跑保持幂等，失败不覆盖旧成功结果。
- 光谱指数在匹配时写项目 FID 输出，未匹配时不产生项目写入。

### 12.2 前端与 Miner 测试

- 当前地图项目 ID 被写入 GeoView URL，直接入口不产生默认 ID。
- GeoView 在分类和光谱请求中传递项目 ID，并正确展示独立或项目同步摘要。
- 矿山弹窗显示后端返回的真实年份，不保留 2016/2022 硬编码。
- 后端 4xx 业务错误显示原始消息，不退化成通用网络异常。

### 12.3 集成验证

- 后端、GeoView、Miner 单元测试与构建通过。
- Compose 七个容器保持运行，带健康检查的服务为 `healthy`。
- 实际预检从 401 变为成功，未登录真实请求仍为 401。
- 使用一个已知匹配当前项目矿山的测试 TIFF，验证分类、最近历史年份矩阵、指数输出和矿山弹窗一致。
- 使用一个不匹配当前项目矿山的 TIFF，验证 GeoView 有结果而项目目录、数据集和弹窗均无新增记录。
- 切换到另一项目重复测试，确认前一项目 KML 和结果均不被读取。

## 13. 验收标准

1. 截图中的“网络异常”不再出现，合法登录用户可创建推理任务。
2. 项目地图进入解译平台后，任务只关联当前项目的活动矿山资源。
3. 无项目或无矿山匹配的 TIFF 只在解译平台展示。
4. 匹配矿山的地物分类、变化矩阵和光谱指数能在对应项目、对应 FID 弹窗读取。
5. 变化矩阵使用最近更早年份；无历史年份时不伪造变化。
6. 大理与昆明交叉读取、交叉匹配和交叉写入测试全部失败。
7. 现有推理任务状态、CPU 回退、历史只读数据和项目 API 保持兼容。
