# 性能优化规划（2026-09-09 制定）

原则：只优化**实测**瓶颈，每项措施先有基线数字、后有复测数字；不为"看起来更快"改代码（与开发规范第五节、测试手册技巧一致）。

## 一、实测基线（2026-09-08/09，真实栈）

测试对象：矿山 fid 696 的 ROI（约 150m×130m，单瓦片 240×248）；数据来源为任务 `stage_durations`（推理流水线已内置逐阶段计时）。

| 场景 | 纯推理阶段 | 任务总计 | 备注 |
| --- | --- | --- | --- |
| CPU 推理（cuda 不可见回退） | 11.7 s | ~13.5 s | bounds_filter 0.21s、tiles 0.23s、其余 <0.1s |
| GPU 推理（RTX 5060, cuda:0）首前向 | 4.1 s | 页面视角 ~35 s | 含 CUDA 上下文初始化 |
| GPU 推理 warm（同一 worker 连续任务） | **0.36 s** | ~0.8 s | 台账耗时列实测（任务 329e0206） |
| 提速比 | cold ≈2.9×；**warm ≈20–32×**（小瓦片） | — | GPU 与 CPU 结果一致；大瓦片倍率需再测 |

关键事实：
1. **inference 阶段占任务耗时 88%–97%**，其他阶段（切图/分发/坐标转换）合计 <1.5s——优化火力必须集中在推理执行本身；
2. `INFERENCE_MAX_CONCURRENCY=1`：任务串行，多矿山批量场景 GPU 大部分时间空转；
3. 瓦片逐张前向：`run_inference_with_model` 每瓦片单独调用 `inference_model`，GPU 批处理能力未利用；
4. 10.7 GB 大底图（Level_15）切片时长**未测**，切片并行度 `SPATIAL_TILE_PROCESSES=4` 未调优；
5. 任务首帧偶发失败后回退成功（GPU 上下文初始化窗口），已观察 1 例，需在连续运行验证中统计频率；
6. 2026-09-09 补充：台账耗时列上线后首批真实数据——warm GPU 0.36s / CPU 7.1s（同瓦片），另有 1 例 CPU 回退任务 31.9s，量化了回退的代价，支撑「短期措施 3」的必要性。

## 二、措施分级

### 已完成
- ✅ GPU 接线（compose 叠加 `docker-compose.gpu.yml`）：单瓦片 ≈2.9× 提速；
- ✅ 逐阶段计时随任务落库（`stage_durations`/`total_seconds`），台账可导出耗时——所有后续优化用数据说话。

### 短期（1–2 周，本轮起执行）
1. **台账增加耗时列**：台账 xlsx 增加"推理耗时/总耗时"，让每次导出都沉淀性能数据（已完成）；
2. **建立大底图切片/推理基线**（✅ 2026-09-09 完成，样本：F 盘洱源县图，2.59GB、19302×44104、约 0.9m/px、CGCS2000 投影 EPSG:4521）：
   - **切片**：zoom 8–15 全图重采样总耗时 **108 秒**（4 进程 gdal2tiles），产出 1083 张瓦片 / 65MB，瓦片服务抽查 200；跨投影（CGCS2000→WebMercator）由 gdal2tiles 自动完成，无需预处理；
   - **推理**：整图登记后发起项目化推理，墙钟 **17 秒**（其中纯流水线 2.0s、GPU 推理 0.46s），路由按矿山 ROI 窗口读取大图（命中 1 座矿山 fid 2704），未做全图扫描——ROI 裁剪策略对超大影像天然友好；
   - **遗留注意**：切片完成自动激活新底图（resource 3），原大理底图（resource 2）置为 retained；当前**没有公开的"重新激活旧底图"接口**，如需恢复要手工改库或补接口；
3. **首帧失败统计**：连续运行验证中记录"首任务回退"频率，若高频则给 worker 增加上线后自预热（空载前向一次）。

### 中期（需要设计与评审）
4. **瓦片批量前向**（✅ 2026-09-09 已实现，INFERENCE_BATCH_SIZE 默认 1）：同矿山 ROI 实测 3 瓦片规模 batch=1 推理 1.329s vs batch=3 推理 1.429s——小规模无收益（逐瓦片 Python 后处理占主导）；收益随瓦片数增长，**大 ROI（几十至数百瓦片）基准待测**；精度一致性由同一前向实现保证，正确性由 5 项单测（分批/隔离/降级/取消）覆盖；
5. **任务并发**：显存允许时将 `INFERENCE_MAX_CONCURRENCY` 提至 2–3（8GB 卡、模型约 4GB，需实测显存余量），并验证取消/心跳/恢复语义在并发下不变；
6. **切片断点续切**：大底图切片中断后从已完成金字塔层级续切，避免 10GB 级重来。

### 长期（立项另评）
7. 模型导出 ONNX/TensorRT（进一步 2–5×，涉及精度验收与新镜像）；
8. 同影像同年份瓦片结果缓存（跳过重复推理）。

## 三、验收口径

每项优化落地时必须给出：同输入、同机器的前后 `stage_durations` 对比 + 功能回归（推理任务 succeeded、矢量成果 ready）+ 一次连续运行三级验证（重复执行→混合小批次→全量）。没有前后数字的优化不接受。
