# 简化方案对照实验：消除锯齿该怎么算（2026-11-24）

目的：用真实数据和消融实验决定「消除锯齿」的实现，而不是凭经验不断增加算法逻辑。
结论：**采用 C——Shapely 原生拓扑保持简化 + 统一校验 + 降容差重试**，不保留任何自定义几何算法。

## 2. 方案

| 方案 | 做法 | 自定义几何逻辑 |
| --- | --- | --- |
| **A** 已部署 | turf 不保拓扑 Douglas-Peucker → 前端手写有效性检查 → 前端采样式越界检查，不过则容差 ÷4、÷16 重试 | 约 375 行 JavaScript |
| **B** 原生 | `simplify(1e-5, preserve_topology=True)`，不校验、不重试，结果原样采用 | 0 |
| **C** 原生 + 校验 + 重试 | B 的结果交给统一 `evaluate`（与保存同一判定），不过则按 1/4、1/16 容差重试，仍不过就拒绝、保持原样 | 约 25 行，不含任何几何算法 |
| **D** 边界保护 | 标记落在矿山边界上的顶点 → 自由链分段 Douglas-Peucker → 边界链去共线点 → 校验 + 重试 | 104 行 |

另附两个旁证方案：B′、C′ 把 `preserve_topology` 换成 `False`（不保拓扑的 Douglas-Peucker）。

类别定义（互有重叠，各自统计）：**贴边界** = 有顶点落在矿山边界 1e-7 度内；**多环** = 环数 > 1；
**MultiPolygon** = 几何类型；**超限** = 坐标位置数 > 5000；**普通** = 以上都不是。
「越界率」「非法率」的分母是该方案给出变化结果的图斑；「有效简化比例」= 给出的结果能通过保存规则的比例。

## 4. ROI 边界保持

口径：原图斑里两端都落在矿山边界上的边视为贴边边；对它的中点量到简化后边界的距离（只用 GEOS 的 `distance`，
不用线与细带求交——那种做法在 1e-9 量级上数值不稳，最初一版给出的 131% 就是假的）。

| 贴边长度保持（仍贴着边界，≤1e-9 度） | A | **C** | D |
| --- | --- | --- | --- |
| 全量（按长度加权） | 18.2% | 18.4% | 100% |
| 拉开距离（抽样 2 万个贴边界图斑）中位 / P90 / P99 / 最大 | 0.14 / 0.59 / 0.99 / 1.80 m | 0.08 / 0.43 / 0.87 / 1.11 m | 0 |
| 10 厘米以内的占比 | 44.9% | 57.7% | 100% |
| 被切到矿山拐点的图斑数 | 15,045 | 12,834 | 0 |

C 与已部署方案在这一点上持平且略好，最大拉开距离严格等于简化容差（A 的 1.80 米超过了容差）。
D 是唯一能让图斑简化后仍贴着矿山边界的方案——这是它相对 C 唯一的实质优势。

## 5. 顶点压缩的配对比较

「各自成功集合不同」会误导：D 成功的图斑更多（含很多本来就没什么可简化的），所以总量口径下它的压缩率显得低。
只看 C 与 D 都简化成功的 134,278 个图斑：**C 压缩 84.05%，D 压缩 73.67%**。D 并不比 C 简化得更多。

**被简化的图斑里 85% 小于 100 m²**，而默认容差是 1e-5 度（约 1.1 米）。对小图斑，任何方案的面积中位变化都在 15% 以上。
C 把它从 37.5% 降到 15.2%，但没有消除。这是参数问题，需要产品决定（见未解决风险）。

## 7. 简化算法的确定性：GEOS 3.10.3 的一个事实

核对回归数字时发现：同一个图斑，同一份代码，连续两次简化的结论不同。追查结果：

- `simplify(preserve_topology=True)`（GEOS 拓扑保持简化）对少数输入**依赖输入对象的内存地址**：
  同一图斑每次用新建的等价对象调用 200 次，得到 2 种不同输出（151 次对 49 次）。抽样 400 条成果 19,779 个图斑，**7 个（0.035%）**如此。
- `preserve_topology=False`（Douglas-Peucker）是确定的：200 次同一个输出，抽样里 0 个不稳定。
- 引擎的校验兜底让两种输出都合法：要么通过校验返回，要么被拒绝、保持原样。所以**正确性不受影响**，
  受影响的只是「同一个操作每次结果完全一样」和回归计数的最后一位（全量 137,041 / 137,042）。

要不要因此改用 Douglas-Peucker（C′）？两者的数据：

| 144,176 个图斑 | C 拓扑保持 | C′ Douglas-Peucker + 校验 + 重试 |
| --- | --- | --- |
| 有效简化比例 | 95.05% | 95.04% |
| 顶点压缩 | 82.8% | 83.3% |
| 面积变化 中位 / P95 | **13.3% / 34.0%** | 14.3% / 51.0% |
| 确定性 | 0.035% 的图斑不稳定 | 确定 |

**保留 C。** 它的面积变化尾部轻得多（DP 不保拓扑，会把细窄的部分抹掉，大面积变化的尾部重了一半），
而不确定性只出现在 0.035% 的退化输入上且被校验兜底。改用 C′ 只需把 `_simplify_candidate` 里的一个参数改成 `False`，
数据在此，取舍由项目负责人决定。GEOS 3.12+ 是否已消除该不确定性行为未验证（见 §9）。

## 8. 独立实验：Shapely 2.1.2 / GEOS 3.13.1（未升级生产依赖）

在一次性容器里把 Shapely 2.1 临时装到容器内目录，同一份数据：

- **批量计算**：向量化 `is_valid` + `covers` 判全部 144,176 个图斑累计 14.84 秒（每条成果 P50 3.8 ms），
  向量化拓扑保持简化累计 31.56 秒（P50 8.8 ms）；Shapely 1.8.5 逐个循环分别是 44.9 秒和 177.9 秒。约 3 倍与 5.6 倍。
- **判定一致**：GEOS 3.13.1 下全部 144,176 个图斑同样合法，与 GEOS 3.10.3 的结论互为独立印证。
- **`coverage_simplify` 的三种用法**（容差同为 1e-5 度）：

| 用法 | 变化 | 越界 | 非法 | 坐标位置 | 面积总量变化 |
| --- | --- | --- | --- | --- | --- |
| 整份成果做 coverage，外边界也简化 | 144,110 | **13,695（9.5%）** | 0 | 2199 万 → 267 万 | −0.0038% |
| 只简化图斑之间的公共边 | 143,782 | **0** | 0 | 2199 万 → 770 万（−65%） | 0（相对 1e-16） |
| 成果 + 「矿山内没有图斑的部分」虚拟面，只简化公共边 | 144,042 | 0 | 0 | 2199 万 → 629 万（−71%） | −0.014% |

「只简化公共边」是原生能力里最理想的一种：矿山边界不动、相邻图斑的公共边两侧一起简化、面积总量精确守恒，
不需要任何自定义算法。但它有两个前提，本轮都不满足：

1. **生产依赖没有它。** 需要 Shapely ≥ 2.1 与 GEOS ≥ 3.12。
2. **生产成果不满足 GEOS 对 coverage 的严格定义。** `coverage_is_valid` 判 3029 条成果里 2881 条（95%）不是有效 coverage。
   抽 40 条诊断：580 对相邻关系里没有一对有重叠面积，563 对是干净的共边，12 对是 T 形接合，5 对只在一点相接；
   但每个图斑都被标为「有无效边」——公共边两侧的顶点序列没有对齐。原因推测是矢量化一侧的节点对齐（见架构审计 F7、F8），未完全查清。
   上表的 good 结果是在这个前提不成立的条件下得到的，不能据此直接采用。

另外，编辑器的「消除锯齿」只作用于选中的面；用 coverage 简化时，与选中面相邻的未选中面的公共边也会跟着变，
这与「不静默修改无关图斑」相冲突，需要产品先决定是否接受。

## 9. 未解决与建议

| 项 | 说明 | 建议 |
| --- | --- | --- |
| 默认简化容差对小图斑过粗 | 85% 的被简化图斑小于 100 m²，面积中位变化 15%；1000 m² 以上的图斑只有 0.2% | 产品决定：容差按像元尺寸或图斑大小取，或对小于某尺寸的图斑默认不简化 |
| GEOS 3.10.3 拓扑保持简化的不确定性 | 0.035% 的图斑同一输入不同输出；校验兜底保证合法 | 记录为已知限制；升级 GEOS 后重跑 `debug_tps_determinism3.py` 确认是否消除 |
| 简化会把图斑从矿山边界上拉开 | C 与已部署方案约 18% 的贴边长度仍贴着，其余拉开不超过容差（P99 0.87 米） | 若业务要求简化后仍贴着矿山边界，D 是已评估的方案（104 行、P50 慢 50 倍、MultiPolygon 上更差），快照保留在 `engine-D-variant.py` |
| coverage 简化 | GEOS ≥ 3.12 原生支持且效果最好 | 升级依赖前先修矢量化一侧的节点对齐，并决定是否接受相邻图斑公共边同步变化 |
